01 / Overview

The Framework

A clean mental model for how messaging works at Wander. Built around the guest lifecycle, not around one-off blasts.

Core principle: CIO owns the relationship. The app owns the transaction.
Booking confirmations, receipts, and password resets live in the codebase. Pre-trip nurturing, lifecycle automation, newsletters, and re-engagement live here. If it's critical to delivering what a user already purchased → app. If it's about relationship and conversion → CIO.

02 / Segments

Segments

All meaningful segments are dynamic — they auto-update as people meet or leave the criteria. Static segments are for one-off broadcasts only and should be archived after use, not left to accumulate.

Core Segments

NameDefinitionPrimary use
All Active Valid email + not unsubscribed Weekly newsletters, property launches
High Intent Checkout started OR wishlisted a property — no order_completed ever Abandoned cart, price drop, weekly deals targeting
Bookers At least one order_completed ever Re-engagement, recs newsletter, post-trip upsell
Recent Guests Most recent trip_ended within 90 days Rebook nudge, personalised recs newsletter
Lapsed Signed up >90 days ago AND (never booked OR last booking >365 days ago) Win-back campaign entry trigger
In Sales Outreach Attribute bdr_outreach_active = true (set by BDR team via Outreach sync) Suppresses all marketing while sales owns the lead

Operational Segments

NameDefinitionUse
New Sign-Ups Signed up within the last 14 days Suppress from newsletters during onboarding sequence
App Users Has at least one mobile device registered Push notification campaigns
VIPs 3+ completed bookings or total spend above threshold Early access, special offers, concierge touches
Static segment hygiene: When you need to send a one-off blast to a CSV list, upload it as a static segment, use it, then archive it immediately. Static segments should never be reused — create a dynamic segment if you find yourself wanting to reuse one.
03 / Events

Key Events

The behavioral signals that drive campaigns. What you put in the event payload is what you can use for personalization and conditions downstream. Reconcile event names against the tracking plan before using in production.

Booking Funnel

EventWhen firedKey payload properties
checkout_started User reaches the checkout screen property_id, property_name, check_in_date, check_out_date, total_price, guests, image_url
payment_info_entered Payment details submitted (pre-confirmation) Same as checkout_started + booking_id
order_completed Booking confirmed and paid booking_id, property_id, property_name, check_in_date, check_out_date, total_price, nights, guests, image_url, property_address
order_cancelled Booking cancelled (guest or admin) booking_id, property_id, cancellation_reason, refund_amount

Trip Lifecycle

EventWhen firedKey payload properties
trip_started Check-in date reached (backend) booking_id, property_id, property_name, property_address, access_code, check_out_date, wifi_name, wifi_password
check_in_day Morning of check-in day Same as trip_started
trip_ended Check-out date reached (backend) booking_id, property_id, property_name, review_url, nights_stayed
product_reviewed Guest submits a review booking_id, property_id, rating (1–10), review_id

Browsing & Engagement

EventWhen firedKey payload properties

product_added_to_wishlist User saves a property property_id, property_name, location, image_url, price_per_night, bedrooms
product_removed_from_wishlist User removes a saved property property_id
price_refresh Price drops on a property user interacted with property_id, property_name, old_price, new_price, discount_pct, image_url, checkout_url

05 / Newsletters

Newsletters (Broadcasts)

One-time sends to a defined audience. Should always target dynamic segments — not freshly uploaded CSVs. Newsletters are operational, not strategic: they're how we fill the gaps between campaigns with relevant content.

Weekly Property Deals

Curated properties, seasonal deals, and travel prompts. The bread-and-butter broadcast. Targets all active users who aren't currently in onboarding or a trip sequence.

Cadence: Weekly (Thursdays) Audience: All Active minus suppressions Channel: Email Naming: deals-YYYY-MM-DD

New Property Launch

Ad-hoc announcement when a new Wander opens. Should feel like a product launch moment — premium, visual, worth opening. Sent to full active list.

Cadence: Ad-hoc (per launch) Audience: All Active Channel: Email + Push Naming: launch-[property-slug]

Personalised Recs

Uses the rec_for_you_* attributes already computed and synced to CIO profiles. Each user sees their own 3 curated properties. Only send to users with recs_updated_at set.

Cadence: Weekly or biweekly Audience: Bookers + High Intent with rec data Channel: Email Naming: recs-YYYY-MM-DD

Travel Inspiration

Longer-form editorial: destination guides, "best time to visit" roundups, Wander guest stories. Lower frequency, higher brand value. Builds affinity with users not yet ready to book.

Cadence: Monthly Audience: All Active Channel: Email Naming: inspire-YYYY-MM
06 / Transactional

Transactional Emails

These live in the app codebase and are sent directly — not via CIO. They are delivery-critical and must never flow through a marketing system where suppression rules or frequency caps could interfere.

EmailWhenOwner
Booking Confirmation Immediately on order_completed App (Resend)
Payment Receipt Payment processed App / Stripe webhook
Cancellation Confirmation Booking cancelled, refund issued App
Guest Invite Primary guest adds secondary guests App
Password Reset User requests reset App (Better Auth)
Email Verification New account created App (Better Auth)
07 / Suppression Rules

Suppression & Conflict Rules

How we prevent a user from being hit by multiple streams at once. The guiding principle: the more specific and time-sensitive the message, the higher its priority.

Priority Order

1
Transactional — always delivered. Not affected by any suppression rule. Booking confirmations, receipts, cancellation notices.
2
Sales Outreach — if the In Sales Outreach segment is active, all marketing campaigns and newsletters are paused. The sales team owns the relationship until the flag clears.
3
Trip lifecycle — pre-trip, check-in, on-trip, and post-trip campaigns take full priority over newsletters. Users actively in a trip sequence are excluded from that week's broadcast.
4
Onboarding — new sign-ups in their first 14 days are excluded from newsletters. They're in a dedicated welcome sequence.
5
Newsletters & broadcasts — lowest priority. Target the dynamic segments that already exclude groups 2–4 above.

Cancellation — Global Exit Signal

CampaignExit on order_cancelled?Note
Abandoned Checkout ✅ Yes User explicitly cancelled — don't chase
Pre-Trip Series ✅ Yes — immediately Match on booking_id if user has multiple trips
Check-In Day + On-Trip ✅ Yes — immediately Same booking_id matching required
Trip Extensions ✅ Yes — immediately Extension offer is moot if cancelled
Post-Trip Review ⚠️ Case-by-case Skip if trip was cancelled before starting. If late cancel after check-in, use judgment.
Welcome / Onboarding ❌ No Not booking-specific — continue the sequence
